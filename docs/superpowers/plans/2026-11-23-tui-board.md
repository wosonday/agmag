# TUI Board (ratatui) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A full-screen, keyboard-driven project board (`agm board [project]`, and `cd <project>` inside `agm tui`) showing projects, the orchestration tree with live flow edges, the selected agent's detail and conversation, and the project inbox.

**Architecture:** New library module `src/board/` split into pure parts (`flows`, `state`, `theme`, `view`) and one I/O part (`mod.rs`: terminal guard, data load, event loop, effects). Task 0 freezes all shared types and signatures in one compiling scaffold; Tasks 1–4 then run in parallel worktrees, each owning disjoint files; Task 5 integrates.

**Tech Stack:** Rust 2024, `ratatui` 0.30.x (crossterm backend, crossterm 0.29 already in `Cargo.lock`; use `ratatui::crossterm`, do not add `crossterm` as a direct dependency), rusqlite, existing `agmag` modules.

**Spec:** `docs/superpowers/specs/2026-11-23-tui-board-design.md`

## Global Constraints

- Gates for every task: `cargo test`, `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` all clean.
- Unknown values render as `-`; never invent data.
- Every untrusted string (message text, kinds, names, labels, turn summaries, BRANCHES.md values, inbox text) goes through `crate::dashboard::sanitize_one_line` before it reaches a ratatui `Span`.
- Human-only: the board refuses non-TTY and agent callers exactly like `agm tui` (`actions::detect_caller` must return `Caller::User`).
- Raw mode and the alternate screen are always restored: normal exit, error return, and panic.
- Windows 11 is the primary platform. crossterm on Windows emits both `Press` and `Release` key events: only `KeyEventKind::Press` (and `Repeat`) may act.
- `AGM_ASCII=1` → ASCII borders/connectors (`+ - |`), no box-drawing characters.
- No `kill`, `interrupt`, `cleanup`, `policy`, `view`, no mouse, no % progress, no change to the data model, MCP or other CLI commands.
- Refresh every 2 s and right after each action; a failed refresh keeps the last good data and shows the error in the footer.
- Live flow = latest message between the two agents is under 300 000 ms old.
- Theme setting key `board.theme`; values `catppuccin-mocha` (default), `tokyo-night`, `nord`.

## Review Focus

1. Hostile text (ESC/OSC sequences, newlines, CJK/emoji, 500-char labels) in any field → rendered inert, never drawn outside its panel. Test in Task 3.
2. Empty data (no projects; project with no agents; all agents exited; no project chosen yet) → empty-state lines with `-`, no panic. Tests in Tasks 2 and 3.
3. Selection target disappears between refreshes (agent exits, inbox item closed elsewhere) → selection moves to the nearest remaining item and no effect fires with a stale id. Test in Task 2.
4. Tiny terminal (20×6, even 1×1) → no panic, no arithmetic underflow in layout. Test in Task 3.
5. Action fails (reply to an already-resolved item, send to an unknown terminal, done on a missing id) → footer error note, board keeps running. Test in Task 4.

### Task 1: Flows (track A)

**Files:** `src/board/flows.rs`, `src/store/project.rs`; tests in `tests/board_flows_test.rs`.

**Interfaces:** Consumes `AgentView` (`project.rs`), `MessageRow`, `actions::kind_to_english`. Produces the `flows` functions and `Store::pair_latest_messages` exactly as frozen in Task 0.

Rules:
- `pair_latest_messages`: rows whose `from_t` **and** `to_t` are both in `parties`; one row per unordered `(from_t, to_t)` string pair, the one with the highest `id`; empty `parties` → empty. Use `ROW_NUMBER() OVER (PARTITION BY MIN(from_t,to_t), MAX(from_t,to_t) ORDER BY id DESC)` with `numbered_placeholders`.
- `edges`: for each (child, Some(parent)) pick the newest (`ts_ms`, then `id`) row whose ends are one key of the parent and one key of the child, in either direction; no row → no edge. `kind` = `kind_to_english(row.kind)`.
- `parents`, `agent_keys`, `is_live` are already implemented and tested in Task 0; this task implements `edges` and the query.

### Task 2: State and key handling (track B)

**Files:** `src/board/state.rs` (unit tests in-file under `#[cfg(test)]`).

**Interfaces:** Consumes Task 0 types, `actions::KINDS_EN`, `ThemeName::next`. Produces `BoardState::{new,on_key,sync,selected_agent}`.

Behavior (normal mode):

| Key | Effect / state change |
|---|---|
| `Tab` / `BackTab` | cycle `Projects → Orchestration → Detail → Inbox` (reverse for BackTab) |
| `↑`/`k`, `↓`/`j` (and `←`/`h`, `→`/`l` in Orchestration: previous/next agent in display order) | Projects: `sel_project`; Orchestration: `sel_agent`; Detail: `msg_scroll`; Inbox: `sel_inbox`; clamp, no wrap |
| `Enter` | Projects → `Effect::SwitchProject(key)` and set `project`, `panel = Orchestration`; Orchestration → `panel = Detail`; Inbox → `Mode::ShowItem` |
| `r` | selected inbox item → `Mode::Reply{id, ""}`; none → note "no inbox item selected" |
| `d` | selected inbox item → `Mode::ConfirmDone{id}` |
| `s` | selected agent → `Mode::Send{to: address, kind: 0, ""}` |
| `/` | `Mode::Filter{input: filter.clone()}` |
| `t` | `theme = theme.next()`, `Effect::SaveTheme(theme)` |
| `p` | `Mode::PickProject{idx: sel_project}` |
| `?` | `Mode::Help` |
| `q` / `Esc` | `Effect::Quit` |

Popup modes: printable chars append to `input`, `Backspace` pops, `Esc` → `Normal` (no effect). `Reply` + `Enter` with non-blank trimmed input → `Effect::Reply`, back to Normal; blank → stay. `Send`: `Tab` cycles `kind` through `KINDS_EN`; `Enter` non-blank → `Effect::Send{to, kind: KINDS_EN[kind].1, text}`. `ConfirmDone`: `y`/`Y` → `Effect::Done{id}`; any other key → Normal. `Filter`: `Enter` sets `filter = input.trim()`; `Esc` clears `filter`. `PickProject`: ↑↓ moves, `Enter` → `SwitchProject`. `ShowItem`/`Help`: any key → Normal. Key events with `kind == Release` → `Effect::None`, no change. `Ctrl+C` in any mode → `Quit`.

`sync(data)`: clamp `sel_project`; if `sel_agent` no longer in `view.agents` → nearest remaining agent by previous index (or first, or None); same for `sel_inbox` over `view.inbox` ids; if `sel_agent` is None and agents exist → first agent; if the item a popup refers to is gone (`Reply`/`ConfirmDone`/`ShowItem` id not in inbox) → `Mode::Normal` + note "item #N is closed".

### Task 3: View (track C)

**Files:** `src/board/view.rs`; tests `tests/board_view_test.rs` using `ratatui::backend::TestBackend`.

**Interfaces:** Consumes Task 0 types, `flows::{parents, is_live}` and `BoardState::{new, selected_agent}` (implemented in Task 0; tests build `BoardData.edges` by hand and set `BoardState` fields directly, so this track needs neither Task 1 nor Task 2), `theme::Theme`, `crate::dashboard::{sanitize_one_line, format_status}`, `crate::project_render::age_label`, `branches::STATUSES`.

Layout per spec §Layout:
- `layout_mode`: width ≥ 120 and height ≥ 20 → `Wide`; 80–119 and height ≥ 20 → `Medium`; else `Narrow`.
- Wide: left column 20 cols (Projects over Status), middle flexible (orchestration), right 34 cols (agent detail over Messages); inbox 5 rows at the bottom; 1-row footer with key hints or `state.note` (error notes in `theme.error`).
- Medium: no left column; project name in the orchestration title.
- Narrow: stacked orchestration list (one line per agent, indent by depth), detail, inbox.
- Orchestration (Wide/Medium): rows of cards by depth; card = rounded block (ASCII when `ascii`), line 1 `symbol label app/model`, line 2 `doing: <summary> <age>` or stage; selected card border `theme.selected` + bold; `state == "exited"` cards `theme.muted`. Between a parent row and its children draw a connector line labelled `KIND age` from `data.edges`; `theme.accent` when `is_live`, `theme.muted` otherwise, nothing when no edge. Children that do not fit wrap onto the next row.
- Status symbols: `●` working, `◐` blocked/waiting, `✓` done/idle, `✗` error/exited, `-` unknown (ASCII: `* ~ v x -`).
- Detail: app, model/effort, status, task, stage pipeline `wip → ready → merging → merged` (mapping in spec "Builder-check answers"), context gauge (`-` when None), token sparkline (ratatui `Sparkline`) + total, `doing:` + age, last message.
- Messages: `data.conversation`, `from → to KIND age` then wrapped text, scrolled by `msg_scroll`; filtered by `state.filter` (case-insensitive substring on text/from/to).
- Inbox: `#id kind terminal text`, selected row highlighted; popups (`Mode::*`) drawn centered with `Clear`.

### Task 4: Runtime, entry points, tui integration (track D)

**Files:** `src/board/mod.rs` (logic), `src/main.rs`, `src/tui.rs`, `src/dashboard.rs`; tests `tests/board_runtime_test.rs` + in-file unit tests.

**Interfaces:** Consumes everything frozen in Task 0; `project::{compute_roots, list_projects, match_project, load_project_view, git_common_root}`, `dashboard::snapshot`, `Store::{terminals, inbox, setting, set_setting, messages_involving, pair_latest_messages}`, `actions::{detect_caller, reply, send, dismiss_done, DoneFilters}`.

- `require_human`: same check as `tui::run` (both stdin and stdout TTY, `detect_caller(... , tty, false)` is `Caller::User`), same error text with `agm board` instead of `agm tui`.
- `resolve_project`: snapshot → terminals → roots → `list_projects` → `match_project`; `Ambiguous` → error `ambiguous: a, b`; `NotFound` → `no project matching '<q>'`. Called **before** entering raw mode.
- `load_data`: snapshot, `terminals(false)`, `inbox(true)`, `compute_roots`, `list_projects`; if `state.project` is Some → `load_project_view`, `pair_latest_messages(parties of all view agents via flows::agent_keys)`, `flows::edges`; then `state.sync(&data)`; then `conversation = messages_involving(agent_keys(selected), 30)`.
- `apply_effect`: `Reply` → `actions::reply(store, hc, id, &text, now)`; `Done` → `actions::dismiss_done(store, vec![id], DoneFilters::default(), false, true, now)` (identical to `agm done <id>`); `Send` → `actions::send(store, hc, "user", &to, &kind, None, &text, now)`; `SaveTheme` → `set_setting(theme::SETTING_KEY, name.as_str())`; result → `state.note` (`ok: true` "replied to #N" / "closed #N" / "msg #id → to: status" / "theme: name"; errors `ok: false` "error: {e:#}"). Never panics, never returns an error.
- Terminal guard: `trait TermControl { fn enter(&mut self) -> io::Result<()>; fn leave(&mut self) -> io::Result<()>; }`; `struct TermGuard<T: TermControl>` calls `leave` in `Drop` once; the real impl does raw mode + `EnterAlternateScreen` + hide cursor / the reverse. `run` installs a panic hook that calls the real `leave` before the previous hook, and restores the previous hook on exit.
- `run`: theme from `setting(SETTING_KEY)` (`parse`, default on missing/invalid); loop: `scan`, `load_data` (on error keep last data, set error note), `terminal.draw(view::draw(..., std::env::var("AGM_ASCII").as_deref() == Ok("1")))`, `event::poll` until the next refresh; key → `on_key` → `Quit` breaks, `SwitchProject` sets project and reloads, other effects → `apply_effect` then reload immediately.
- `main.rs`: `Board { project: Option<String>, #[arg(long, default_value_t = 2)] refresh: u64 }` with doc comment "Full-screen project board"; `require_human` → optional `resolve_project` → `board::run` with the same `scan` closure `Cmd::Tui` uses.
- `dashboard.rs`: new `TuiCmd::CdText(String)` parsed from `cd -t <q>` (`cd -t` alone → usage error); help/usage text mentions `cd <project>` (board) and `cd -t <project>` (text view).
- `tui.rs`:
  - stdin hand-shake: the reader thread sends a line, then blocks on a `resume` channel before reading the next one; the main loop sends `resume` exactly once after it finished handling each received line. This guarantees no line read is pending while the board owns the console.
  - `Cd(Some(q))` with `Found(key)` → `board::run(store, cfg, &hc, Some(key), refresh, &mut scan)`; error → note; on return force a full repaint (`last_frame = None; after_input = true`) and keep the scope global. `..`/`/` unchanged.
  - `CdText(q)` → today's `Cd(Some(q))` behavior (text project view scope).
